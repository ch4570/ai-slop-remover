# 경량 UI 경로 검증 · 2026-09-09

실제 Codex CLI 실행 8개, 비교 4쌍에서 양쪽 모두 필수 품질 검사를 통과했다.
이번 변경은 알려진 국소 수정의 참조 로딩을 조건화한다. **금액 절감이나 일반적인
품질 향상을 입증한 결과는 아니다.** [사용량·품질·참조 해시](summary.json)와
[추가 라우팅/재사용 관찰](probes.json)을 함께 보아야 한다.

## 관찰 결과

총 토큰은 입력+출력이다. 캐시 읽기와 추론은 각각 그 부분집합이므로 다시 더하지 않았다.
괄호 안은 필수 품질 검사 통과 수다. 참조 읽기는 계측 helper가 본문을 출력한 횟수다.

| 사례 | baseline / candidate 품질 | 총 토큰 baseline → candidate | 참조 읽기 | 명령 호출 |
| --- | --- | --- | --- | --- |
| 간격 한 곳 | pass(3/3) / pass(3/3) | 239,734 → 128,875 | 5 → 2 | 12 → 9 |
| 읽기 전용 진단 | pass(3/3) / pass(3/3) | 196,742 → 135,290 | 9 → 8 | 14 → 12 |
| 빈 상태 문구 | pass(3/3) / pass(3/3) | 198,993 → 167,627 | 6 → 6 | 12 → 12 |
| 페이지 밀도 예외 | pass(5/5) / pass(5/5) | 139,863 → 133,029 | 8 → 3 | 13 → 8 |

간격 수정은 양쪽 모두 같은 한 줄을 바꾸고, 브랜드·문구·저장/복원·375px 포커스를
유지했다. 후보의 참조 본문 출력량은 15,689→8,180바이트였다. 두 문구 실행은 같은
참조 6개, 같은 22,105바이트를 읽었는데도 토큰이 달랐다. 따라서 전체 차이를
스킬 수정의 인과 효과로 해석하지 않는다.

관찰된 총 토큰은 775,332→564,821, 품질 통과 작업당 토큰은
193,833→141,205.25다. 네 쌍 토큰 차이의 중앙값은 −46,409다. 반면 캐시를 제외한
입력은 122,554→123,312로 조금 늘었다. 캐시는 통제하지 않았고 실제 모델 ID와
적용 단가도 없으므로 **금액 비교 가능 쌍은 0/4, 금액은 unavailable**이다.
작업당 전체 비용이나 구독료 절감률로 바꾸어 표현하지 않는다.

모델 실행은 모두 정상 종료했다. 추가 모델 재시도·자식 실행은 없었다. 도구의
비정상 종료 4건도 같은 실행의 사용량에 포함한다: 제품 DESIGN 파일을 참조 helper에
넣었다가 일반 읽기로 복구한 2건, 검색 결과가 없어 종료 코드1을 받은 2건이다.
실패한 호출을 빼고 성공한 호출만 합산하지 않았다.

## 검수와 남은 제품 제약

소스 범위 검사, 설치된 Chrome의 실제 동작 수집, 구현자와 분리한 AI의 의미·화면
검수를 구분했다. 사람이 검수한 것으로 표현하지 않는다. 구현 에이전트에는 브라우저가
없었고, 모두 그 한계를 최종 답변에 남겼다. 이후의 외부 Chrome 관찰을 에이전트가
직접 수행한 검사로 돌려 적지 않았다.

- 진단 사례는 최종 파일 내용·종류·모드가 그대로이며, 원시 명령 기록에서도 제품 쓰기가
  관찰되지 않았다. 후보의 중요도 표기와 목록 순서에는 경미한 불일치가 남았다.
- 문구 사례는 허용된 한국어 값3개, `{query}`, 접근성 이름, 실제 검색어 수정 복구와
  never-populated 상태를 유지했다. 긴 한국어 줄바꿈과 검색 입력 포커스를 직접 봤다.
- 밀도 예외는 두 실행 모두 비교 표의 padding만16→10px로 바꾸고 디자인 문서와
  일치시켰다. 기본 화면의16px·브랜드·열·행 동작은 유지했다.
  후보는 허용된 범위의 셀 간격 변경으로 처리해 SKILL·principles·design-memory만
  읽었다. 이를 넓은 배색·구조 작업의 참조 로딩 증거로 사용하지 않는다.
- 좁은 표의 첫 포커스 오른쪽 잘림은 **원본에도 있던 제약**이다. 원본·baseline·candidate의
  전후 화면을 각각 열고, 실제 가로 wheel로45px 이동한 뒤 전체 포커스 표시와
  Enter/Tab/Space 행 실행을 확인했다. 이 통과는 기존 잘림을 해결했다는 뜻이 아니다.
  물리 기기·스크린리더·OS IME·키보드만으로 가로 스크롤하는 동작은 미검증이다.

## 참조 재사용과 넓은 작업

별도 후보 전용 CLI 프로브 2개도 실제 실행했다. 이들은 제품 구현 품질이나 비용의
비교 분모에는 넣지 않는다.

1. 같은 문맥에서 파일이 그대로라는 후속 조건에는 추가 읽기 없이 기존 내용을
   재사용했다. 이 조건은 작업이 제공했으며 독립적인 새 해시 검사를 증명하지 않는다.
   평가자가 DESIGN을 바꾼 다음에는 새 문서를 읽고24px의 새 역할을 반영했다.
   문맥 내용이 없다는 **시뮬레이션** 후에는 관련 내용을 전체 재독했다. 실제 자동
   압축/복원은 검증하지 않았다. 변경 단계에서 CSS의 해시 검사 후 전체 읽기를
   중복한 비효율도 남겼다.
2. 화면 전체의 배색·배치 계획에서는 요청이 참조 파일명을 지정하지 않았는데도
   art-direction, color-composition, layout-composition을 읽었다. 브랜드와 주요
   상태를 유지하고 기존 저장 오류를 별도 flow 수정으로 구분했다. 이는 읽기 전용
   **계획** 관찰이며 전체 화면 재구현 품질의 전후 검증은 아니다.

선택한 SKILL 전체 읽기와 호스트 우선 규칙은 유지한다. 재사용에는 같은 경로·리비전/해시와
현재 문맥의 내용이 필요하다. 파일 변경·새 페이지/테마·문맥 손실·사용자 지시에는 다시
읽는다. 이번 채택 범위는 검증한 국소 수정과 기존 계약 보존이며, 모든 작업이 더 싸거나
자동으로 불필요한 읽기를 완전히 제거한다는 보장은 없다.

## 실행 조건과 보관

- baseline: `035af3f3f8a4bea9c3529eab2c2be997a76ac219`.
  후보: 네 스킬/참조 파일 변경을 고정한 snapshot
  `d6172b390a6c2fe2d3b94c7dba884b77c242cc1b32be014a63b3ca1bc5dd928b`.
- 같은 사례의 TASK·초기 fixture·도구·설정을 맞췄다. 사례마다 시작 순서를 번갈아
  배치했으며, 반복은 한 번뿐이다. 설치된 스킬 자동 발견이 아닌 명시적 source snapshot 실행이다.
- Codex CLI0.153.4의 기본 모델/설정, 새 ephemeral context, 자식 실행·네트워크·앱·플러그인
  비활성화 조건이다. 요청 모델도 null, 관찰 모델도 미제공이다. 호스트 hooks는 끄지 않았다.
  `skip_host_skill_discovery`가 개발 중이라는 비치명적 경고를 원본에 보존했다.
- 외부 브라우저는 Chrome152.0.7977.83 / Node25.2.1, 임시 프로필과 합성 loopback 제품이다.
  사용량은 직접 구현 CLI의 전체 호출이며 준비·외부 평가·검수·유지보수 비용은 제외한다.
- helper 로그는 파일 본문 출력과 경로/해시를 기록하지만 모델의 실제 소비를 증명하지 않는다.
  baseline 간격 실행의 첫 SKILL 호출은 helper 출력 기록은 있으나 CLI의 captured output이
  비어 있다. 이 계측 공백을 ‘읽지 않음’으로 바꾸지 않았다.
- 문구 실행의 자동 경로 경고 각1건은 명령 안의 정규식 리터럴을 경로로 오인한 것이다.
  두 원본 명령을 직접 확인했으며 외부 파일 접근으로 보지 않았다.

원시 프롬프트·명령·모델 출력은 Git에 넣지 않았다. 실행 환경의 로컬 데이터 폴더
`.local/share/lutriva/evaluations/2026-09-09-issue21-l9I62k/`에 전체 증거636개 파일과
SHA-256 inventory를 보존했다. `inventory.json` 해시는
`69866115f2b00f8f80374d549f46fca6da4a22f267dad588a106a4309d8ad93a`다.
공개 요약만으로 원본의 진실성을 재검증할 수는 없다. 원본 접근 없이 실제 실행을
재현했다고 주장하지 않는다.

로컬 증거가 있으면 `trials-record/evaluator/scripts/collect_usage.py compare`에
그 디렉터리의 `pairs.json`을 주어 집계를 재계산할 수 있다. 기존 schema1 품질 결과와
원본 SHA에 묶인 sidecar를 사용하며 모델을 다시 실행하지 않는다. 자세한 계약은
[평가 안내](../../README.md)의 Optional usage accounting 절을 따른다.

- Python396개 통과(브라우저47개는 일반 발견에서 skip), npm24개 통과.
  package/manifest, JavaScript 구문, `git diff --check` 통과. 위 실제 Chrome8개 실행은

  6/6 검사 통과. 권장 제목 등 advisory13개는 실행 품질 점수가 아니다.

  학습 검증의 ‘not … erase history’ HIGH 경고를 원문에서 확인해 오탐으로 분류했다.
  공유 코드의 두 제한된 읽기 전용 Git 호출, assets/LICENSE 배치는 기존 구조다.
  LLM 분석을 하지 않아 도구의 completeness=false를 유지한다. 완전한 보안 검증으로 쓰지 않는다.
