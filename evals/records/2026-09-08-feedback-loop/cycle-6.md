## 문구 검수

제품 6개 파일 중 `locales/ko.json`의 지정된 값 9개만 다르고 키·각 문자열의
변수·나머지 한국어·영어·JS/HTML/CSS/DESIGN은 보존됐다. 검수자는 원본 16개,
결과 22개 검사를 실행했다. 결과에만 관련 보존 검사 6개를 더했으므로 점수 전후
향상으로 비교하지 않는다. 양쪽의 실행 예외는 0개다.

실제 Enter 입력 후 각 실행의 임시 다운로드 경로에 `개인 메모.csv`가 생겼으며,
UTF-8 BOM·두 저장 제목·필드 양끝 따옴표를 포함한 준비된 Blob과 파일 바이트를
대조했다. 링크 실행 전 폴더가 빈 것도 확인했다. 이는 이 headless 환경의 실제
파일 생성이며 앱이 기기 다운로드 완료를 감지하거나 모든 기기에서 성공함을 뜻하지 않는다.
저장/내보내기 실패 뒤 입력·저장 데이터 유지와 재시도, 같은 프로필 reload,
320px CDP 터치 입력과 키보드 링크 접근도 관찰했다.

실행 위치 준비에 `.focus()`/`.select()`와 합성 localStorage를 사용했다. 대기
캡처는 기존 120ms 타이머만 페이지 메모리에서 보류했으므로 대기 성능 측정이
아니다. 글자 확대는 Chrome 기본 글자 16→24→32px 설정 및 실제 computed 값
확인이며, 밀도 진단의 요소별 CSS 확대·OS 크기·페이지 zoom과 구분한다.
실제 다운로드·프로필은 출력 아래의 임시 경로에 제한했다. 사용자 프로필이나
전역 다운로드 폴더에 쓰지 않았다.

검수자는 결과 캡처 16개 전부와 원본 9개를 직접 열었다. 원본의 나머지 4개는
캡처만 했다. `browser.json`의 초기 `visuallyInspected:false`는 캡처 시점 값이고
후속 실제 열람 목록은 `visual-review.json`에 따로 있다. 320px·긴 제목·200%
문구는 세로로 길지만 읽고 행동에 접근할 수 있어 길이/줄바꿈은 선택 의견으로 남겼다.

부모도 별도 20개 상태/데이터 검사를 양쪽에서 실행해 모두 통과했다. 이는 합성
DOM 입력·320×900 mobile:true·Blob 읽기이고 링크 다운로드는 하지 않았다.
허위 클라우드/모든 기기/기기 저장 완료 문구도 이 20개에 통과하므로 부모가 실제
문장과 app.js/데이터를 따로 대조했다. 결과는 브라우저 임시 저장·보존한 입력의
재시도·파일 준비를 사실대로 설명했다. 사용자 이해 속도나 실수율은 측정하지 않았다.

부모가 원본 CSV 둘을 직접 읽고 원시 JSON과 크기·해시를 대조한 결과 둘 다
168바이트, SHA-256 `4cd715a7864f9666193242193f6190dc5f403c24a24b45bf2360fad49ea7c495`다.
이 실제 다운로드의 긴 제목에는 내부 큰따옴표가 없다. 부모는 처음 이 사실로
전체 escaping 실행도 미검증이라고 메모했으나 독립 감사가 결과 전용 마지막
검사를 찾아 그 판단을 바로잡았다. 마지막에는 `수요일 "프로젝트" 회의, 준비물 확인`을
다시 저장한 뒤 미저장 편집값과 구분해 export하고, **Blob** 84바이트에서 내부
큰따옴표 doubling을 실제 검사했다. 기록된 해시는
`9023c175170d6d4d7dc3bc20b91db8b654b7429b4e03bb14165c92fafc466477`이며,
doubling을 뺀 82바이트 반대 기대값의 해시는 다르다. 따라서 escaping은 결과의
추가 Blob에서 검증됐고 실제 다운로드된 두 파일에서는 자극하지 않았다.
원문 보고서의 준비/다운로드 근거를 이 순서대로 읽어야 하며, 부모의 초기 오독과
교정은 메모와 감사에 보존한다. 이를 제품 결함이나 스킬 지침 누락으로 세지 않는다.

## 관찰 범위와 다음 사이클

실제 Chrome은 `152.0.7977.83`, macOS·Node 26.8.1이다. blind 검수는 각 세션
시작의 `Browser.getVersion`을 기록했고 부모 초기 진단/문구 재검사는 전후 버전을
기록했다. 시작만 관찰한 세션의 종료 버전까지 같았다고 주장하지 않는다.
임시 프로필과 target guard는 네트워크·업데이트의 완전한 격리를 보장하지 않는다.
물리 기기·다른 브라우저·OS/페이지 zoom·IME·스크린리더·전체 WCAG·원격 CI는
미검증이다. 모든 부모 이미지 열람도 검수자의 개수에 더해 독립 표본 수로 세지 않는다.

밤샘 목표는 진행 중이다. 다음에 자동 포커스 노출을 개선한다면 원래 과업을
재해석하지 않고 추가 권한과 성공 조건을 명시한 새 제품 과업으로 분리한다.
이번 결과만으로 공통 스킬 규칙이나 일반적인 자율 학습 효과를 추가하지 않는다.

진단과 부모20개 문구 검사는 제품 경로·새 출력 경로를 받아 재실행할 수 있다.
압축·해시 일치는 자료 의미의 정확성이나 지침의 일반적 향상을 입증하지 않는다.

압축 생성 뒤 `npm test`를 다시 실행해 20/20 통과와 정확한 설치 payload를
확인했다. 약4.3MB의 새 원시 압축은 npm/설치 payload에 들어가지 않았다.
`npm run check` 재실행과 기존 다섯 압축을 포함한 여섯 `SHA256SUMS` 검사도
통과했다. 이 후속 npm 원시 로그는 `/tmp/lutriva-cycle6-post-archive-9nq0y2`에
있으며 이미 생성한 tar에 포함했다고 주장하지 않는다.

[최종 압축 독립 검토 원문](cycle-6-archive-review.md)은 자기 참조 해시를 피하도록
tar 밖에 보존한다. 새 문맥의 검토자가 정확한 tar 집합393개를 다시 확인하고
새 경로에 해제했다. 최초 파일시스템 경로의 원시 문자열 대조는 한글 CSV 두
이름 때문에 종료1이었다. tar/inventory의 NFC 이름이 macOS에서 해제 후
`readdir`에는 NFD로 반환됐다. 최초 누락2/추가2 기록은 보존했으며, 파일 내용을
고치거나 tar 검사기를 느슨하게 바꾸지 않았다. 명시적 NFC 변환에서 이름 충돌을
거부한 별도 대조는 393개 경로·크기·해시 모두 일치했다. 원시 파일명 문자열까지
동일하다고 주장하지 않는다.

추출한 휴대용 ArrowRight 진단 세 조건과 부모 문구 검사 원본20/결과20도 새
Chrome에서 모두 재현됐다. 별도 근거 검사는 종료코드와 분리해 복구 필드·네 변
포함·단계별 값/이벤트·target guard·전후 .83·입력 해시를 확인했다. 검토자는
복구 전후 viewport PNG6개와 문구 결과 full-page PNG2개를 직접 열었다.
이 재실행은 blind 검수 전체28조건/38검사를 다시 실행한 것이 아니며, 실제
CSV는 보관된 다운로드 바이트를 읽어 확인했다. 원시 최종 검토 로그와 재실행
자료는 원문의 별도 임시 경로에 있고 이 tar에 포함했다고 주장하지 않는다.
