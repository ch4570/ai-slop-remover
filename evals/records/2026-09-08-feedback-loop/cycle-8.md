## 문제와 수정

설치 기록의 정수 schema `1`을 JSON `true`로 바꾸면 `--status`는 정상적으로
`unverifiable`이라고 보고하지만, `--dry-run`과 실제 재설치는 정상 기록처럼
받아들였다. 최초 독립 탐색자는 정확한 기존 install.py를 두 스킬의 축소된
schema2/version2.0.0 fixture로 실행해 새 형제 스킬 복사를 재현했다.
기존 설치 파일/변조 기록의 바이트·mtime은 같았다. 이는 덮어쓰기/데이터
손실이 아니라 검증 불가인 대상이 있으면 새 복사 전에 거부한다는 계약 위반이다.

원인은 `existing_is_identical()`의 원시 JSON 객체 동등 비교다. Python은
`True == 1`, `1.0 == 1`을 참으로 보지만, 상태 점검의 기존
`read_installation_record()`는 schema가 정확한 정수여야 한다고 검사한다.
재설치 전 검사도 이 기존 검증기를 사용하도록 한 줄을 바꿨다. 소유 기록의
형식을 먼저 확인한 뒤 기존 객체·파일 집합·콘텐츠 해시 비교를 수행하며,
모든 선택 대상의 사전 검사 뒤 복사하는 순서는 그대로다. 자동 복구·갱신·
기존 파일 덮어쓰기는 추가하지 않았다.

## 적용 조건과 남은 범위

표준 형식의 유효한 레거시/현재 기록은 기존 무변경 재설치를 유지한다.
다만 예전 로더가 받아들인 모든 입력의 동작까지 같다고 주장하지 않는다.
레거시 로더는 root의 원래 기록 이름만 예약하지만 기록 검증기는 어느 깊이든
두 기록 이름을 거부한다. 또한 파일명만의 충돌 검사보다 엄격한 case-folded
파일/상위 경로 중첩 검사도 있다. 이런 특이 payload의 기록은 상태 검사가
이미 검증 불가로 보던 것이며, 이제 재설치도 거부한다. 후자의 case-sensitive
파일시스템 예 등은 소스에서 도출한 적용 경계이지 이번에 실행한 추가 재현이
아니다. 이 수정에서 로더를 바꾸거나 자동으로 기록을 복구하지 않았다.

실행은 macOS의 기존 Python3.9.6, 추가 설치 suite는 기존 Python3.12.14다.
Windows/Linux, 강제 종료·동시 설치·권한 변경 경합은 새로 검증하지 않았다.
브라우저 전용 suite는 이 설치 기록 수정과 무관해 실행하지 않았으며, 이전
결과를 이번 실행 결과로 옮기지 않는다. 실제 사용자 스킬·프로필·전역 설정·
원격 저장소를 건드리거나 새 의존성을 설치하지 않았다.

## 압축의 독립 재현과 후속 보완

[최종 독립 검토](cycle-8-archive-review.md)는 원문 그대로 보존했으며 SHA-256은
`2a70422636f2201059f6193c6d5747891a342bc442866f983a1f4c12435ec666`다.
검수자는 새 디렉터리에 압축을 풀어 같은 검사 소스로 원본과 수정본을 각각
다시 실행했다. 원본은 128/160단언 통과·종료1, 수정본은 160/160단언
통과·종료0이었고 수집 오류는 양쪽 모두 없었다. 추출한 3,219파일의
경로·모드·mtime·크기·해시는 재현 전후 같았다. 실제 CLI 기록과 스냅샷,
남아 있는 설치 파일까지 확인해 원본의 새 형제 복사와 수정본의 전체 프로젝트
보존을 대조했다. 별도 원시 기록 감사도 같은 결과를 확인했으며 재현 횟수를
새로운 시나리오 종류로 합산하지 않는다.

검토는 기존 quiet 로그만으로 47개 skip의 이유나 별도 Python의 정확한 패치
버전까지 독립 확인할 수 없다는 증거 범위도 밝혔다. 이에 부모가 압축 생성 뒤
`python3 -B -m unittest discover -s tests -v`를 새로 실행했다. 293개 중
246개가 통과했고, 건너뛴 47개 모두의 이유가 명시적 브라우저 opt-in 조건인
`AI_SLOP_BROWSER_TESTS=1`임을 원시 출력에서 확인했다. 기존
`/opt/homebrew/bin/python3.12`에서도 같은 프로세스가 `sys.version`을 출력하고
설치 suite를 실행하게 해 Python 3.12.14와 80개 통과를 함께 기록했다.

두 후속 실행의 정확한 명령·시각·종료값·stdout/stderr는 위 후속 로그 경로의
`python-verbose.*`, `python312-versioned.*`에 있다. 이는 독립 검토가 읽은
원래 quiet 로그나 고정 압축에 소급해 추가된 증거가 아니다. 독립 검토 원문은
수정하지 않았으며 검수자의 새 재현 자료도 검토문에 적힌 별도 임시 경로에 있다.
