## 관찰과 수정

임시 프로젝트를 대상으로 인자 `--repo PROJECT --agent codex --status -- --help`를
직접 Python 설치기에 주면 종료2와 `unrecognized arguments: -- --help`가
나온다. npm 래퍼는 같은 인자로 종료0·도움말을 출력하고 상태 보고를 하지 않았다.
일반 도움말과 올바른 상태 조회는 종료0으로 정상이며 임시 프로젝트의 기존
파일 바이트·mtime은 양쪽 모두 같았다. 실제 설치나 데이터 손실 재현은 아니다.

원인은 모든 인자에 대한 `args.includes('--help')`/`args.includes('-h')`였다.
첫 `--` 앞의 구간에서만 도움말 옵션을 찾도록 바꿨다. 도움말이 그 앞에 있으면
Python 없이 기존 도움말을 보여주고, 그 뒤에만 있으면 **원래 인자를 그대로**
Python에 넘겨 파서의 오류를 보존한다. 옵션 종료 표시나 이후 인자를 버리지
않으며 Python 감지, 설치기, 지원 명령·별칭, 배포 버전은 바꾸지 않았다.

수정 전 래퍼 SHA-256:
`8712d315eaeee755118b2984b416a284158a5aa9caf824b2177061952bbec1a3`.
수정 후:
`e4b54b244018100ebe79c768862d43a280d6805739f88b15c950ea95e5951ada`.

## 실제 검증

- `node --test '--test-name-pattern=option terminator' tests/npm-cli.test.mjs`:
  기본/`install` × `--help`/`-h`의 4개가 수정 전 종료값 `0 !== 2`로 실패하고
  수정 후 모두 통과했다. 양쪽 테스트 소스는 동일하다.
- `npm test`: 24개 통과. 위 회귀는 이 수에 포함된다. 일반 도움말·버전의
  Python 불필요, 첫 `--` 전 도움말, 공백 경로, 두 목적지 설치·재설치·상태
  조회, 실제 npm payload와 두 설치 별칭을 포함한다. 두 별칭에서도
  `--list -- --help`가 종료2·파서 오류이고 stdout은 비어 있음을 확인했다.
- `npm run check:js`: JavaScript 구문 검사 통과. 브라우저 키 입력·시작의
  npm 단위 검사는 실제 브라우저를 띄우지 않는다.
- `npm run check`, `git diff --check`: 배포 해시·7개 스킬·24개 정적 계약·
  참조/의존성·Python 구문과 공백 검사 통과. 정적 계약은 UI 과업 실행이 아니다.

CHANGELOG/검증 문서를 반영하고 manifest를 갱신한 뒤 `npm test` 24개를
다시 통과했다. 반복 실행을 새 커버리지로 더하지 않는다.

[별도 읽기 전용 검토](cycle-9-review.md)에서는 래퍼 12개
사례가 통과했다. 이 중 경계 오류 4개는 직접 Python 실행과 종료값·stdout·
stderr가 정확히 같았다. 검사자는 프로젝트 root와 파일의 경로·종류·모드·
mtime·바이트 보존과 검토한 소스 해시 불변도 확인했다. 이 검토는 정상
미설치 상태와 도움말·오류를 검사했으며 npm 패키지 설치나 수정 전 실행을
대신 수행한 것은 아니다. 추가 차단 이슈는 발견하지 않았다.

실행 환경은 macOS, Node 26.8.1, Python 3.9.6이다. 별도 Windows/Linux 실행,
실제 브라우저와 전체 Python suite는 이번에 실행하지 않았다. 이전 사이클의
통과를 이번 실행으로 합산하지 않는다. 실제 사용자 설치·전역 설정·원격 저장소를
변경하지 않았다. 스킬 지침의 품질 개선이나 모델 학습 효과를 이 수정으로 주장하지 않는다.
