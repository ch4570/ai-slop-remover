## 키 입력 도구와 환경 한계

별도 임시 어댑터들에서 Enter 문자 누락, Shift 비트 오류, Windows 숫자를
macOS native key code로 함께 보내는 오류가 반복됐다. `pressKey`는 Tab·Enter·
Escape·Space와 boolean Shift만 허용하고 잘못된 옵션을 전송 전에 거부한다.
Shift는 비트 8, Enter/Space 문자는 key-down에만 넣으며 native code는 보내지
않는다. 검색/범위 수집기의 기존 Enter/Tab만 이 helper로 바꿨다. 기존 suite
판정 기준·출력 schema·타이밍은 바꾸지 않았다. 단위 검사의 정확한 이벤트/순서와
실제 Chrome의 신뢰된 이벤트·Tab/Shift-Tab·Enter 폼 제출·Space 체크박스를
구분했다. 제품 시험은 이전 고정 harness를 사용해 이 도구 변경과 섞지 않았다.

준비 중 의도하지 않은 `chrome://settings/help` target이 생긴 실행을 중단했다.
실행 중 helper 경로의 .76과 종료 후 실행 파일 .83이 달랐으나 사전 executable
버전이 없어 변경 원인/시각을 알 수 없다. 업데이트 UI 조작·설치·버전 복귀는
실행하지 않았다. 해당 실행과 버전 미기록 비교는 제외하고 기록된 새 실행을
사용했다. 프로필 분리나 유한한 target guard를 네트워크/업데이트 격리로 주장하지
않는다. 초기 실패·probe·버전 미기록 자료와 제외 이유도 원문 그대로 보존한다.

네이티브 select 선택은 headless CDP에서 검증되지 않아 실제 Tab 접근 뒤
명시적인 합성 값 준비로 필터 적용을 검사했다. 한국어는 committed text이지
OS IME 조합이 아니다. 물리 키보드/터치·스크린리더 음성·다른 브라우저·글자 확대·
원격 CI·설치된 호스트 자동 발견은 미검증이다. 이 단일 제품 개선과 도구 회귀
통과를 스킬 버전 비교나 일반적인 자율 학습 효과로 해석하지 않는다.

같은 소스에서 두 메서드를 순서대로 다시 실행하자 각각 통과했지만 이를 첫
전체 suite의 통과로 바꾸지 않았다. 원시 실패·단독 재실행 로그를 모두 남겼다.

포트 뒤 `undefined`가 붙은 주소를 만들어 같은 `Invalid URL`을 던졌다. 정상
두 줄 대조군은 주소 생성을 지나 다음 연결 단계까지 갔다. 처음 읽기에 성공하면
내용과 상관없이 준비됐다고 간주하는 기존 결함이다. 실제 첫 두 실패의 원시
시작 파일은 보존되지 않았으므로 그 원인이 같다는 연결은 추정으로 남긴다.

수정은 유효한 포트와 `/devtools/browser/…` 두 줄이 생길 때까지 기존 100회·
100ms 제한 안에서 기다리는 것이다. 제품 판단 기준은 바꾸지 않았다. 새 Node
검사는 spawn/읽기/socket과 타이머를 제어해 불완전→완성, 즉시 정상, 끝까지

수정 전 세 검사 중 두 실패·한 통과에서 수정 후 세 통과로 바뀌었다. CRLF도
별도 호환성 대조군으로 추가했다. 이는 Windows 실행 결과나 실제 브라우저가
