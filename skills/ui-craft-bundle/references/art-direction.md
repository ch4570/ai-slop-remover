# Art direction grounded in the product

## Diagnose structure before styling

Identify the highest-impact cause from the actual screen. Treat these as clues, not a forbidden-style list:

| Symptom | Question | Possible correction |
| --- | --- | --- |
| Every object occupies the same rounded card | Do users compare, scan, edit, or browse? | Rows, tables, grouped lists, or timelines can expose relationships. Keep cards where they represent meaningful objects. |
| Giant heading consumes a working screen | Does the user need persuasion or to perform a task? | Give the working object and primary controls more room. |
| Decorative badges, glows, icons | Which encode actual state, category, or action? | Remove elements with no semantic job. |
| Every section looks equally prominent | What must be noticed first? | Establish a dominant region, supporting region, and quieter metadata. |
| Interchangeable SaaS dashboard | What is distinctive about this domain? | Show real units, object relationships, vocabulary, and workflows. |
| Beige, serif, thin borders everywhere | Was an old template replaced by a new one? | Re-evaluate structure and type from the domain. |
| Empty space but cramped data | Where do users need separation versus adjacency? | Spend whitespace on grouping and reading. |

## Choose one coherent direction

Set density, content width, type roles, spatial rhythm, surface hierarchy, and one deliberate visual characteristic. Explain it through the product: document-like annotations for reading, route lines for travel, or compact status bands for operations. Do not force a novelty quota or mandatory asymmetry.

If the user asks for options, present meaningfully different structures or interaction models. Otherwise choose a direction and implement it. Preserve brand assets and typography when provided. Do not replace familiar typefaces solely because a skill calls them generic.

Build hierarchy with size, weight, contrast, position, grouping, and content. Use color as one contributor. Make icon weights and corner treatments coherent without requiring one radius everywhere. A working screen can be plain when its job benefits from clarity.

## Design with real content

- Use domain labels and action verbs. Replace vague “Get started” only when a precise action exists.
- Exercise long titles, missing values, zero results, large values, and realistic statuses. Include supported scripts such as Korean; check wrapping instead of forcing single-line text.
- Align comparable numbers and units. Keep metadata adjacent to its object.
- Do not add stock art or fabricated statistics to occupy space. Use imagery when it communicates information the user needs.
- Adapt content order and interaction at narrow widths rather than shrinking the desktop. Preserve access to secondary actions.

## Critique with evidence

Write: observed element → effect on the task → concrete change. Distinguish usability defects from style preferences. “Purple is AI slop” is not evidence; “five unrelated actions share identical emphasis, hiding the primary action” is actionable.

If the result can be relabeled as an unrelated product without meaningful changes, check whether real domain content and tasks are missing. Do not add ornament merely to pass this heuristic.
