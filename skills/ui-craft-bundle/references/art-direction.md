# Art direction grounded in the product

## Diagnose structure before styling

Identify the highest-impact cause from the actual screen. When a symptom needs a concrete correction, use [anti-slop methods](anti-slop-methods.md): task priority, meaningful grouping, comparison structure, emphasis, content specificity, and state behavior. Each method includes a tradeoff and a recheck; choose only the relevant entries.

Do not replace one preset with another. Cards, gradients, familiar fonts, or a beige/serif palette are not defects by themselves. Diagnose what obscures the task and retain what already serves it.

## Choose one coherent direction

Set density, content width, type roles, spatial rhythm, surface hierarchy, and one deliberate visual characteristic. Explain it through the product: document-like annotations for reading, route lines for travel, or compact status bands for operations. Do not force a novelty quota or mandatory asymmetry.

If the user asks for options, vary the requested dimension meaningfully: color roles and emphasis for palette choices, structure or interaction only when those are in scope. Otherwise choose a direction and implement it. Preserve brand assets and typography when provided. Do not replace familiar typefaces solely because a skill calls them generic.

Build hierarchy with size, weight, contrast, position, grouping, and content. Use color as one contributor. Make icon weights and corner treatments coherent without requiring one radius everywhere. A working screen can be plain when its job benefits from clarity.

## Compose color and space together

For palette work, use [color composition](color-composition.md) to assign foreground/background roles, balance emphasis across the actual page, and check adjacent surfaces and states. A set of attractive swatches or passing contrast ratios does not establish a coherent screen.

For placement work, use [layout composition](layout-composition.md) to define the visual order, allocate width from real content, establish shared alignment anchors, and distinguish spacing within and between groups. Decide the page's working shape before refining individual cards.

Before a broad implementation, make a compact decision in the work note: what leads, what supports it, where the action belongs, which color roles carry emphasis, and how the arrangement changes under width pressure. Reuse established decisions when they already answer this. Inspect the resulting full page and its detailed states together; correct a dominant support panel or cramped primary region before adding polish.

## Design with real content

- Use domain labels and action verbs. Replace vague “Get started” only when a precise action exists.
- Exercise long titles, missing values, zero results, large values, and realistic statuses. Include supported scripts such as Korean; check wrapping instead of forcing single-line text.
- Align comparable numbers and units. Keep metadata adjacent to its object.
- Do not add stock art or fabricated statistics to occupy space. Use imagery when it communicates information the user needs.
- Adapt content order and interaction at narrow widths rather than shrinking the desktop. Preserve access to secondary actions.

## Critique with evidence

Write: observed element → effect on the task → concrete change. Distinguish usability defects from style preferences. “Purple is AI slop” is not evidence; “five unrelated actions share identical emphasis, hiding the primary action” is actionable.

If the result can be relabeled as an unrelated product without meaningful changes, check whether real domain content and tasks are missing. Do not add ornament merely to pass this heuristic.
