# Completion follows evidence

- A claim must be no broader than the check that supports it.
- Separate implementation, build/type checks, visually inspected images, exercised behavior, and unknowns.
- Prioritize task failure, lost input, false success, inaccessible essentials, and major layout breakage over cosmetic preferences.
- Verify the requested change proportionally; do not make unrelated coverage or a beauty score a completion gate.
- Keep product code and live data read-only while using authorized existing tests and disposable fixtures.
- Missing tools limit particular claims; they do not erase useful evidence already available.
- Follow the canonical [verification guidance](../../ui-craft-bundle/references/verification.md) and report a concrete recheck when evidence or behavior is insufficient.
