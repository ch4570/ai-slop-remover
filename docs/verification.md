독립 검토에서 오래된 활성 포인터 복원에 따른 세대 되감기, 손상된 현재·직전 규칙에서 복귀 불가, 오래된 후보 컨텍스트 공급을 재현하고 수정했다. 전환 기록의 연속성, 채택 당시 릴리스 해시, 현재 부모·세대·기반·정책과 후보의 호환성을 검사한다. 손상된 현재 규칙은 유효한 포인터·전환 기록을 유지한 상태에서 정상 이전본이나 공통본으로 복귀할 수 있다. 누락·분기·중단된 전환 기록은 임의로 초기화하지 않는다.

별도 검토자가 임시 프로젝트에서 같은 적격 평가를 두 프로세스로 동시에 채택하는 시도를 3회 수행했다. 매번 한쪽만 채택하고 다른 쪽은 잠금 오류로 거부됐으며, generation·완료된 전환 기록·활성 규칙 수는 각각 1이었다. Windows 줄바꿈을 재현한 CRLF 입력으로 후보 본문·해시 비교 테스트 2개도 통과했다. Windows 운영체제 자체에서 수행한 검증은 아니다.

PR 전 재검토에서는 Git 인덱스 검사 실패를 비Git 환경처럼 허용하는 초기화 경로와 평가 `record.json`의 스키마·ID 검증 누락을 추가로 수정했다. 실제 손상 인덱스와 추적 후 삭제된 경로를 거부하고, 정상 비Git·Git 실행파일 부재는 지원한다. 잘못된 평가 스키마·ID·알 수 없는 필드·해시·파일 맵은 릴리스 생성 전에 거부한다. 별도 임시 복사본에서 각 검증 로직을 제거하자 새 회귀 검사가 실제로 실패하는 것도 확인했다.

첫 Windows CI에서 npm 검사 1개가 같은 디렉터리의 `RUNNER~1` 단축 경로와 `runneradmin` 전체 경로를 다르게 비교해 실패했다. 설치된 CLI는 정상 실행됐으며, 테스트의 경로 비교를 기존 설치 상태 검사와 같은 `realpathSync.native`로 수정했다. 수정 후 원격 재검증 결과는 해당 PR head의 CI에 기록한다.

Node 20/Python 3.9 기본 런타임, Node 22 이상의 선택적 Chrome 검사와 기존 CI 행렬은 유지하며 새 의존성은 추가하지 않았다.

## 2.2.0 브랜드와 CLI 호환성 (릴리스 당시 검증)

검증일: 2026-09-07. Lutriva 이름, README·배너, npm 패키지와 CLI 별칭을 반영했다. `skills/`의 지침은 2.1.0과 동일하다.

- Python 전체 80개·npm CLI 7개 테스트 통과. 새 `lutriva`와 기존 `ai-slop-remover`를 각각 실제 설치한 뒤 `--version`·`--list` 출력이 같은지 확인했다. 새 명령이 없던 기존 패키지에서 확장한 검사가 실패하는 것도 먼저 확인했다.
- 새 임시 npm 캐시에서 로컬 tarball을 `npm exec --offline`으로 실행해 `lutriva --version`이 2.2.0을 반환하는지 확인했다. 레지스트리 설치와는 별개다.
- 배포 목록 65개 파일의 해시와 링크·의존성을 검증했다. npm tarball은 manifest·package.json·CLI를 포함해 68개 파일이며 배너와 브랜드 안내도 포함한다. 독립 정적 검토에서 누락된 파일이나 호환성 문제는 발견되지 않았다.
- GitHub Markdown API가 렌더링한 두 README를 별도 Chrome의 로컬 미리보기에서 확인했다. 1280px 밝은·어두운 배경과 375px 화면에서 배너·본문·설치 안내를 검수했고, 모바일 설치 표를 두 열로 줄여 호출명이 잘게 끊어지는 문제를 고쳤다. 페이지 가로 넘침·내부 앵커와 키보드로 상세 안내를 여는 동작을 확인했다.

화면 검수는 GitHub Markdown HTML에 로컬 미리보기 스타일을 적용한 결과다. 인증된 GitHub 애플리케이션 전체나 실제 휴대 기기를 검사한 것은 아니다. npm 게시, Windows 실행, 새 모델 비교 평가는 이번 검증에 포함하지 않았다. 아래 2.1.0 결과를 브랜드 변경의 UI 품질 향상 증거로 해석하지 않는다.

독립 검토에서 발견한 일반 Enter 성공 경로 누락과 좁은 화면 오류 상태 누락을 보완했다. 드라이버는 실제 브라우저 키 입력으로 일반 Enter를 확인한다. 비교기는 관찰된 실패가 있으면 미실행 항목보다 먼저 changes-required를 반환한다.

### 한계

- IME 검사는 합성 composition 이벤트로 handler를 확인했다. 실제 OS 한글 입력기·물리 기기·스크린리더는 검증하지 않았다.
- 브라우저 동작과 화면 관찰을 별도 기록했다. 화면 캡처나 모델 자체 보고만으로 동작 통과를 판단하지 않았다.
- 호스트의 자동 스킬 발견은 별도 미검증이다. 이번 에이전트는 지정한 스킬 snapshot을 명시적으로 읽었다.
- 비교기는 기록의 구조와 비교 가능성을 검증하며 증거 자체의 진실성을 자동 보증하지 않는다.
- Tier 2/3와 전용 보안 스캐너는 미실행이며 Tier 1을 완전한 보안 감사로 해석하지 않는다.
- 설치기의 동시 실행·강제 종료 복구는 검증하지 않았다. 여러 스킬 설치 전체의 원자성을 보장하지 않는다.
- npm 런타임은 Node 20 이상과 Python 3.9 이상이다. 선택적 브라우저 평가 드라이버는 Node 22 이상과 기존 Chrome이 필요하다. 검증 환경은 macOS/Node 25.2.1/npm 11.7.0이며 Windows 실행은 미검증이다.
- 이 문서의 검증 결과는 npm 레지스트리 게시 성공의 증거가 아니다. 실제 게시 상태는 릴리스 안내에 별도로 기록한다.
