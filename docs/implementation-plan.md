# AI Slop Remover 스킬 세트 작업 계획

- 기준: 원본 `47a1fdd` (`main`), 작업 브랜치 `feature/ai-slop-skill-set`.
- 목표: 사용자의 핵심 작업이 명확하고 조작·피드백·실패 복구가 자연스러운 UI/UX를 만드는 재사용 스킬 세트.
- 범위: 기존 디자인·플랫폼 지침 재사용, 독립 호출 스킬, 다중 스킬 설치, 문서와 검증. 실제 제품 UI나 새 외부 의존성은 추가하지 않는다.

## 변경 순서와 단순화

1. 기존 단일 번들의 해시·dry-run·설치·동일 재설치 동작을 임시 경로에서 검증한다. 초기 검증 통과.
2. 설치기의 기존 안전 계약을 회귀 테스트로 고정한 다음 다중 스킬 설치를 추가한다.
3. `ui-craft-bundle`의 플랫폼·디자인 참조를 재사용한다. `ai-slop-remover`가 진단, 시각 정리, 흐름, 문구, 검수 스킬을 필요한 범위만 연결한다.
4. 기존 `--dest`는 단일 스킬 경로 계약을 유지한다. `--repo --agent`는 전체 세트, `--skill`은 의존성을 포함한 선택 설치를 지원한다.
5. 해시 manifest를 배포 파일의 기준으로 유지한다. Git 체크아웃과 배포용 ZIP 양쪽에서 설치되도록 소스 관리 파일과 배포 payload의 경계를 분리한다.
6. 테스트, 문서 링크·스킬 메타데이터·의존성 검증, 임시 프로젝트 설치를 실행한다. 완료한 변경을 커밋·푸시한다.

## 인수 조건

- 스킬은 현재 제품·브랜드·스택을 먼저 확인하고 실제 사용자의 작업을 기준으로 판단한다.
- 좁은 수정이 전체 리디자인으로 번지지 않는다. 추가 의존성·외부 도구 설치를 강제하지 않는다.
- 모션은 조작을 지연하지 않으며 reduced motion·반복 입력을 다룬다.
- 문구는 행동·결과·복구를 설명하고 허위 성공이나 조작적 UX를 만들지 않는다.
- 키보드·터치·작은 화면·긴 한국어·오류/빈 상태를 관련 범위에서 확인한다.
- 구현·빌드·화면 관찰·동작 시험·미검증을 구분한다. 점수만으로 완료를 선언하지 않는다.
- 손상된 파일, 경로 탈출, 심볼릭 링크, 사용자 수정본 덮어쓰기를 거부하고 재설치는 멱등적이다.
- 설치 성공을 런타임 발견이나 실제 UI 개선 효과의 증거로 과장하지 않는다.
